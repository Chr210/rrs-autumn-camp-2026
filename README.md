# RoboCup Autumn Camp 2026 Competition

## 1. コンペティションの概要

本コンペティションでは，RoboCup Rescue Simulation（RRS）における災害救助エージェントを開発します．

参加者には，サンプルエージェントをコンペティション用に調整した初期エージェントと，愛知大学周辺を対象としたマップ・シナリオを配布します．

参加者は **救急隊（Ambulance Team）または消防隊（Fire Brigade）** のいずれかを担当し，担当部隊で使用するモジュールを改良します．

開発では，配布されたマップ・シナリオでシミュレーションを実行し，LogViewerなどを用いてエージェントの行動やシミュレーション結果を確認しながら，より良い結果を得られるようにモジュールを改善していきます．

最終評価では，参加者が開発した救急隊と消防隊を組み合わせてシミュレーションを実行します．すべての組み合わせを評価し，最も高いスコアを獲得した組み合わせを構成する救急隊と消防隊の開発者を優勝者とします．

## 2. 目的

本コンペティションの目的は，RRSにおけるエージェント開発を通して，各救助部隊の役割やモジュールの構成について理解を深めることです．

また，救急隊と消防隊をそれぞれ開発し，最終的に異なる参加者が開発したエージェントを組み合わせて評価することで，各救助部隊の役割だけでなく，異なる種類のエージェント間の相互作用を考慮した開発を経験することも目指します．

さらに，LogViewerなどを用いてシミュレーション結果やエージェントの行動を分析し，問題点の発見と改善を繰り返すことで，エージェント開発における分析・改善の流れを経験することも目的とします．

## 3. コンペティションのルール

### 参加形式

- 個人またはチームで参加できます．
- チームの人数に制限はありません．
- 各参加者・チームは，救急隊（Ambulance Team）または消防隊（Fire Brigade）のいずれかを選択してください．
- チームで参加する場合は，チーム内で協力して1つのエージェントを開発してください．

### 開発に関するルール

- 担当する救助部隊で使用するコードを開発できます．担当外の部隊のコードは変更できません．
- 配布されたモジュールの改良に加え，独自モジュールやUtilityなどの補助クラス・関数を新しく作成できます．複数のモジュールを開発しても構いません．
- 追加するコードは自分の`src/<team>/`内に配置してください．通常のPython importで利用する補助コードは，`module.yaml`への登録は不要です．チームパッケージ全体が提出・統合の対象となります．
- ADFのTacticsクラスの変更は禁止します．
- `config/module.yaml`は運営側で管理します．参加者は原則として変更しないでください．
- ADFのModuleManager経由で読み込む独自モジュールなど，設定の追加・変更が必要な場合は，IssuesまたはPRで運営に連絡してください．運営が担当部隊の専用設定へ反映します．
- `DefaultSearch`などの共通設定は変更できません．
- 独自のPathPlanningやClusteringなども実装できます．担当部隊専用の設定から利用してください．[コードと設定の具体例](docs/development.md#独自pathplanningclusteringの追加例)を参照してください．
- Police Force（PF）は本コンペティションでは使用しません．

## 4. 開発について

### 開発環境

本コンペティションでは，ADF-Pythonのサンプルエージェントをベースとした初期エージェントを使用します．

初期エージェントとPython依存の定義は，本リポジトリに含まれています．シミュレーション用サーバは別途取得します．

エージェント開発に不慣れな方は，[RRSチュートリアル](https://rcsimjp.github.io/rrs-tutorials/docs/intro/)も参考にしてください．

### 開発の始め方

1. 本リポジトリをフォークしてください．
2. フォークしたリポジトリをローカル環境にクローンしてください．
3. 担当する救助部隊の初期エージェントを，自分のチーム用ディレクトリにコピーしてください．
4. 担当するモジュールを改良してください．
5. シミュレーションを実行し，改良結果を確認してください．

具体的な手順は[開発・提出ガイド](docs/development.md)を参照してください．AT担当のチームフォルダは，リポジトリのルートで次のように作成できます．

```sh
uv sync --locked
uv run python tools/create_team.py at myteam
cd submissions/at/myteam
uv sync --locked
uv run python main.py -a 20 -f 20 -ac 0 -fs 0
```

FB担当の場合は，`at`を`fb`に置き換えてください．エージェントの起動前に，別ターミナルでシミュレーション用サーバを起動してください．

### 使用するマップ・シナリオ

本コンペティションでは，愛知大学周辺を対象としたマップ・シナリオを使用します．

マップ・シナリオは[`map/aichi_university/`](map/aichi_university/)に含まれています．救急隊20台，消防隊20台，建物内の救助対象の市民35人，避難所3か所を配置しています．

### シミュレーションによる動作確認

開発中は，担当する救助部隊と，運営側が用意したもう一方の救助部隊の初期エージェントを組み合わせてシミュレーションを実行します．

例えば，救急隊を担当する場合は，開発中の救急隊と初期状態の消防隊を組み合わせて実行します．

LogViewerなどを使用し，エージェントの行動やシミュレーション結果を確認しながら改善を進めてください．

## 5. エージェントの提出について

開発したエージェントは，**GitHubのPull Request（PR）** を使用して提出してください．

### 提出方法

1. フォークしたリポジトリでエージェントを開発してください．
2. `submissions/`ディレクトリ内に，担当部隊とチーム名に対応するディレクトリを作成してください．
3. `main.py`，`config/`，`src/`，依存ファイルを含むチームフォルダ一式を配置してください．`.venv`や実行ログは含めないでください．
4. 変更をコミットし，本リポジトリにPull Requestを作成してください．
5. Pull Requestには，チーム名，参加者名，担当部隊，改良した内容を記載してください．

提出されたPull Requestは運営側で確認します．

なお，提出されたエージェントのソースコードは，他の参加者も閲覧できます．

## 6. 最終評価

最終評価では，提出された救急隊と消防隊のすべての組み合わせについてシミュレーションを実行します．

評価条件は以下のとおりです．

| 項目 | 内容 |
|---|---|
| 評価対象 | 救急隊と消防隊の組み合わせ |
| マップ・シナリオ | 配布された評価用マップ・シナリオ |
| Police Force | なし |
| 乱数シード | 1種類（すべての組み合わせで共通） |
| 評価指標 | RSL21スコア |
| 順位決定 | 最も高いスコアを獲得した組み合わせを優勝とする |

評価に使用する乱数シードは，すべての組み合わせで共通とします．

最終評価の結果は，本リポジトリで公開する予定です．

## 7. 質問・不具合報告
